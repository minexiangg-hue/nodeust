# 首轮内测反馈修复（2026-09-10）

## 实现与验收口径

1. 草稿：在「我的帖子」工具栏新增草稿箱图标；弹窗列出历史草稿，可继续编辑或删除。保存草稿允许内容尚未填全；再次保存同一草稿会更新该条，发布成功后移出草稿箱。保存或发布失败时保留表单内容。草稿使用 `node:drafts:<账号 ID>` 存在当前浏览器，支持刷新恢复，不能跨设备同步；清理浏览器数据会清除草稿。
2. 移除「我的匹配」「匿名私聊」「收藏」「我的帖子」工具栏中的「返回地图」按钮。使用原有导航返回探索广场。
3. 广场的地图／列表偏好只由视图切换按钮改变。进入私聊、匹配等页面再回来保留视图、分区和筛选条件，包括手机底栏和自己的帖子跳转。
4. 本科生宿舍、研究生宿舍等分区同时约束地图和列表。匹配及收藏不受广场当前分区限制。
5. 「我的帖子」的展示中和已关闭帖子可编辑类型、地点、标题、正文及换宿路线。服务器同时检查作者与帖子状态；编辑不会更换帖子 ID、重新开启已关闭帖子或删除已有对话。已删除／已匹配帖子不可编辑。新增和编辑共用内容及地点校验，不能借编辑绕过联系方式隐私规则。
6. 公告栏默认完全收起；展开后才标记当前公告已读。铃铛仅在有未读公告时点亮。已读状态按账号保存在本浏览器；新增公告或公告内容变化会再次提醒。
7. 私聊导航和每个会话仅显示对方发来的未读消息数量。空会话、自己的消息和系统消息不触发提醒。普通消息逐条显示已读／未读；自己发出的消息以对方确认的阅读位置判断状态。
8. 聊天已读保存在已有参与者表的 `last_read_at` 字段，跨设备有效。单纯获取消息不会标记已读；会话可见且滚动到最新内容后才确认。后台标签页不确认新消息，翻看历史时不强制滚动到底部。确认消息必须属于此会话，更新只前进、不后退。
9. 全局操作提示约 4.5 秒自动关闭，连续操作重新计时。表单内的保存失败信息保留，供用户修正或重试。
10. 发布表单的地点选择与广场个人地点标签同步；选择器直接展示地点名称。网络失败保留原值，显示错误；保存期间禁用相关操作，避免多个地点请求交错。
11. 地点显示有效需求数与「选择该地点标签的人数」。人数只计有效账号的手动地点标签，不代表实时在线／实际在场人数。只提供汇总数，不返回人员身份。两项计数查询完整数据库，不受广场最近 100 条帖子限制。
